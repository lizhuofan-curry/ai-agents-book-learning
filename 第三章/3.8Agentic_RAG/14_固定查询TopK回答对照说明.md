# 固定第三条查询：Top-5与Top-10回答对照

2026-10-24：代码准备，正式模型调用待用户运行。

## 运行

确认Ollama与既有qwen3.5:9b可用，在项目根目录执行，或在VS Code打开13脚本运行：

```bash
.venv/bin/python "第三章/3.8Agentic_RAG/我的代码/13_固定查询Top5与Top10回答对照.py"
```

两组各最多1次本机模型请求，共最多2次；不预热、不重试、不安装、不下载、不读云端密钥。不运行之前的自主检索循环。`--preview`校验资料与固定排名，不请求模型或生成正式结果；预览会在本机执行该固定查询以检查上下文。

## 为什么这样做

上一轮第三条模型查询“累犯认定条件及前科对量刑的影响规定”把第六十五条排在第8，Top-5无法送给模型。现在固定该查询、原始问题、回答提示、模型和采样，重新建立两组独立对话，只改变返回前5或前10个完整片段。Top-10的前5项严格等于Top-5；只有Top-10含第六十五条。

本轮使用相同的固定问答提示，不包含之前Agent多轮历史或缺口提示；所以只比较本轮两组，不能把新结果与旧Agent差异都归因于Top-K。模型看原问题与本组片段，不额外告知目标编号或标准答案。只允许answer，禁止模型追加search。

使用03的相同模型请求配置：temperature=0、seed=42、think=false、2048输出上限、16384上下文、600秒读取超时。序列为Top-5后Top-10，没有随机化，时间只作运行记录。

## 看什么

- 目标是否进入上下文、是否出现在回答引用中？这两项仅机械统计。
- 模型是否正确理解目标中的条件与例外？不能只看到“累犯”就断言适用。
- 是否仍有前科相关无依据断言？是否分清材料不足和案情条件不足？
- 新增片段是否引入无关内容或误导，输入token增加多少？

Top-10额外增加5个片段，不仅增加目标一条；即使回答改善，也不能将全部变化归因于某个目标条文。该问题法律情境未充分明确，冻结资料用于实验，不能按机械目标命中认证实际适用。

## 保存与状态

记录独立保存到`运行结果/topk_answer_时间/record.json`，含两组完整上下文、请求、原HTTP响应、引用和token。旧记录与代码不改。标记`TOPK_ANSWER_COMPARISON_SAVED`代表流程已保存，仍需查看各组状态与人工语义核对；某组失败会留存并继续另一组，不重试，用户中断则停止整个实验。

这是已知失败后的固定查询机制实验，不是Agent自主检索能力提升，也不代表Top-10在其他问题上更优。先保留真实结果再决定后续范围。

离线预览以及3项适配测试通过：固定来源与嵌套上下文、单次回答及越界引用拒绝、追加查询和截断不重试。模拟材料不算正式结果。
