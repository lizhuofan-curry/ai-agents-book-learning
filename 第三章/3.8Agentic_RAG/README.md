## 第一步比较什么

固定官方7道题、完整刑法文档，构建506个片段的BM25索引。沿用官方标准库中文单字/双字分词，明确固定这条路线，避免jieba安装状态改变结果。

| 路线 | 操作 |
| --- | --- |
| 单次查询 | 直接用原始问题检索Top-5 |
| 预标注分解查询 | 使用官方事先写好的子查询，每次Top-5，去重后取并集 |
| 扩大候选的单次查询 | 保持原始问题，将Top-K扩大到5×子查询数，辅助观察候选数量因素 |

每条查询记录分词、完整命中片段、BM25分数、累计命中及遗漏的目标条文。指标按片段开头的完整条文编号精确匹配，逐题算证据召回，再按题平均；不是回答正确率。相同返回位置预算不等于相同计算成本，也不消除预标注查询的优势。

官方数据中的subqueries已事先标注，01没有模型推理、没有真正的自主停止判断，不能称为已完成真实ReAct。官方README的数字基于288文档全库，本步只有完整刑法单文档，不能直接照用或声称复现同一指标。第一步不生成法律回答；文本作为冻结检索资料使用，未核验现行法律适用性。

## 观察顺序

1. 看简单题：改写是否真的改变命中？
2. 看hard_4：原问题包含多个方面，子查询分别找到了哪些目标条文？
3. 看扩大候选的单次查询：多拿片段能否补齐，还是查询表达仍有影响？
4. 保留未提升、负结果；不能从这7题得出普遍优劣。

第一步核对后，第二步再用本机模型自行选择检索式、观察结果、决定追加或停止，并保留每轮模型请求与工具轨迹。第二步03代码已准备待用户运行，不把预写子查询替代成模型成绩。后续再衔接个人wiki混合RAG交付。
