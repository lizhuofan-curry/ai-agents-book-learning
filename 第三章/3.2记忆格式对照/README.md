## 比较什么

3-1建立了评估流程；3-2改变记忆表示策略，检查同样的信息怎样保存更有用。

| 模式 | 命令中的名称 | 模型应生成的记忆形态 | 重点观察 |
| --- | --- | --- | --- |
| Simple Notes | notes | 字符串数组，每条为一个简短事实 | 事实是否零散，实体之间的联系是否丢失 |
| Enhanced Notes | enhanced_notes | 字符串数组，每条为保留上下文的段落 | 人物、事件、时间和状态是否说清楚，内容是否冗余 |
| JSON Cards | json_cards | 类别→子类别→键值组成的对象 | 分类是否合理，不同人的信息是否混淆 |
| Advanced JSON Cards | advanced_json_cards | 卡片数组，带来源背景、人物、关系、时间、状态与facts | 是否保留跨会话关联，额外结构花费多少token和时间 |

模式对应的是记忆组织策略，不只是把同一份内容重新排版。每种模式使用其官方提示词重新生成记忆，再在新会话里根据该记忆答题。

## 四组统一配置

qwen3:4b；qwen-recommended采样（temperature=0.7、top_p=0.8、top_k=20、min_p=0）；seed=37；think=false；上下文窗口32768；记忆/答题输出上限6000/1200。每组独立从空记忆开始，不读取其他组记忆。

3-1已暴露1200 token答题截断问题。当前小规模预实验沿用该预算，先检查四种输出能否完整生成；截断照实统计，不能据截断题无分数宣称某种格式内容最差。如需调整预算，应先另立配置，四组使用相同新预算，不拼接不同预算的结果。通过预实验后再安排三层用例扩展。

记录生成输入/输出token、记忆与答题分别的token、最后成功记忆检查点的UTF-8字节数、请求耗时、完成状态及独立评分。字节数不是token数，记录耗时含请求开销。一次运行的冷启动、固定执行顺序和随机性会影响耗时，不能当作稳定速度排名。
