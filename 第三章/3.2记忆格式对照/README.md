## 比较什么

3-1建立了评估流程；3-2改变记忆表示策略，检查同样的信息怎样保存更有用。

| 模式 | 命令中的名称 | 模型应生成的记忆形态 | 重点观察 |
| --- | --- | --- | --- |
| Simple Notes | notes | 字符串数组，每条为一个简短事实 | 事实是否零散，实体之间的联系是否丢失 |
| Enhanced Notes | enhanced_notes | 字符串数组，每条为保留上下文的段落 | 人物、事件、时间和状态是否说清楚，内容是否冗余 |
| JSON Cards | json_cards | 类别→子类别→键值组成的对象 | 分类是否合理，不同人的信息是否混淆 |
| Advanced JSON Cards | advanced_json_cards | 卡片数组，带来源背景、人物、关系、时间、状态与facts | 是否保留跨会话关联，额外结构花费多少token和时间 |

模式对应的是记忆组织策略，不只是把同一份内容重新排版。每种模式使用其官方提示词重新生成记忆，再在新会话里根据该记忆答题。

四组全部使用--memory-format json原输出路线。--mode才是本实验比较的四种记忆策略；--memory-format决定接口如何约束输出。原notes专用Schema不适用于JSON卡片，因此不能只对两组加Schema再把差异解释为记忆策略的影响。3-1的银行Schema成绩只作背景，不复用为这轮notes对照。

3-1已暴露1200 token答题截断问题。当前小规模预实验沿用该预算，先检查四种输出能否完整生成；截断照实统计，不能据截断题无分数宣称某种格式内容最差。如需调整预算，应先另立配置，四组使用相同新预算，不拼接不同预算的结果。通过预实验后再安排三层用例扩展。

记录生成输入/输出token、记忆与答题分别的token、最后成功记忆检查点的UTF-8字节数、请求耗时、完成状态及独立评分。字节数不是token数，记录耗时含请求开销。一次运行的冷启动、固定执行顺序和随机性会影响耗时，不能当作稳定速度排名。

## 恢复与评分

恢复时指定实际打印的预实验目录；不要再次省略--batch创建重复试验。恢复跳过已成功和已失败的组，不自动重试。running状态只在日志能证明请求已结束时恢复，否则保留为unresolved并先人工核对。

```powershell
& 'E:\AI_Agents_Book\.venv\Scripts\python.exe' 'E:\AI_Agents_Book\第三章\3.2记忆格式对照\我的代码\01_四格式单题对照.py' --stage writer --batch '替换为实际预实验目录'
```

生成结果核对后，由用户另行运行评分，最多4次DeepSeek请求，可能计费；只有完整回答才能评分，不重跑本机生成。

```powershell
& 'E:\AI_Agents_Book\.venv\Scripts\python.exe' 'E:\AI_Agents_Book\第三章\3.2记忆格式对照\我的代码\01_四格式单题对照.py' --stage judge --batch '替换为实际预实验目录'
```

--stage summary只核对和汇总，不请求模型。三个阶段均可加--preview，零网络、零子进程，不写入运行结果。

同一个批次只能同时运行一个进程。运行期间用.run.lock防止重复请求；正常退出会删除锁。异常断电后如留下锁，先确认原进程已退出再处理，不自动删除锁或重复请求。
