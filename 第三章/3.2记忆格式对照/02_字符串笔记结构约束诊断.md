# 实验3-2：字符串笔记结构约束诊断

日期：2026-10-17。当前仅完成方案与预览，尚未实际运行本轮Enhanced Notes诊断。

## 为什么先做这个诊断

银行单题四格式原JSON预实验已收尾：两组笔记格式失败，普通卡片答题截断，高级卡片完整但因路由号归属错误被裁判否决。只有1/4组得到完整评分，不能据此比较四种记忆策略的内容能力。

原JSON输出约束只要求输出JSON，没有在接口层规定memory必须是字符串数组。官方提示要求Simple Notes和Enhanced Notes使用字符串数组，但本轮模型都生成了对象。下一步只检查这个接口约束问题，保持模型、官方提示、采样、窗口和生成预算一致。

## 已有的简短笔记诊断参考

本轮notes原JSON记录：official_writer_20261017_152825_771379。此前notes Schema记录：official_writer_20261016_231521_488574。

逐字段核对发现，两份首次记忆请求只有format字段不同：前者为json，后者为memory字符串数组的Schema；模型digest、完整会话、提示、采样、seed、窗口和6000输出上限一致。原JSON组格式失败；已有Schema组生成42条合法笔记并完成答题，该题评分通过。此证据只作单题格式诊断参考，不将旧Schema成绩导入原JSON四组批次，也不能据此断言所有格式或所有用例的效果。

## 下一步：Enhanced Notes只增加Schema约束

继续同一官方银行题、qwen3:4b、enhanced_notes、推荐采样、seed=37、窗口32768、记忆/答题上限6000/1200。唯一计划改变的是memory-format，从json改为schema。Schema只要求memory为字符串数组，不预填账号、路由号或事实，不追加短记忆指令，不改变官方提示。

```powershell
& 'E:\AI_Agents_Book\.venv\Scripts\python.exe' 'E:\AI_Agents_Book\第三章\3.1用户记忆评估\我的代码\02_官方用例生成记忆与回答.py' --case layer1_01_bank_account --model qwen3:4b --mode enhanced_notes --memory-format schema --sampling-profile qwen-recommended
```

最多2次本机推理，另有1次模型列表查询，无自动重试，不调用DeepSeek。--preview已通过，助手未代运行。

此处使用3-1目录中的共享单题入口，其mode参数支持增强笔记；原始记录仍保存到共享运行结果目录。记录中的generation_variant=schema_format_diagnostic明确标记为诊断，与原JSON四格式批次分开，不修改原失败。

## 返回后检查什么

1. 是否完整结束，memory是否为字符串数组；格式通过不等于内容正确。
2. 每条是否仍是带上下文的段落，是否保留人物、事件、时间、状态与归属，而不是退化成孤立字段。
3. 是否同时保留两家银行的信息，并把账号与各自路由号正确关联。
4. 最终回答是否完整、是否与记忆一致；若截断，仍保留失败，不把分析中的一句话截取成答案。
5. 核对新旧增强笔记首次请求是否确实只有format不同。只有完整回答才另行安排独立评分。

该诊断不形成四格式排名，不代表完整3-2完成。后续若提高答题预算或为卡片加入结构约束，应继续另立协议与记录，控制变动因素后再安排正式四组及三层扩展。
