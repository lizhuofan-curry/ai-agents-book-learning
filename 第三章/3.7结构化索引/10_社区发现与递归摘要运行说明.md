```

```

## 做什么

1. 复用06的冻结来源与引句检查；从原始模型图和助手修订图分别生成无向、无权简单投影，用Louvain（seed=42）分组。原图、方向与多关系不改写。
2. 展示原图11组、修订图3个社区。算法分组不是人工主题分类，也不能用社区数衡量图的正确性。
3. 只将助手修订图中带原文引句的14条关系作为摘要叶子，不使用尚未逐条认证的实体描述。关系依然属于助手编辑、用户语义审阅待确认的输入。
4. 分别生成3份社区摘要；跨社区关系另生成1份摘要，避免漏掉连接不同社区的关系。再用4份摘要生成上层总摘要。总摘要只接收下层摘要，不重新读取原文，便于观察压缩及遗漏的累积。
5. 对3条固定英文查询，展示仅关系叶子与全部层级的词频余弦Top-3，并将摘要引用逐层展开到关系ID。源引句、完整请求、原始响应和输入哈希都保存于record.json。

最多5次本机模型请求，每次输出上限2048 token、600秒读取超时；无预热、无自动重试、无嵌入或云端调用。请求失败、输出截断、JSON异常、引用为空或越界即停止，保留已有记录；不会用截断文本或助手编写内容冒充成功的模型摘要。

## 看什么

- 哪些实体聚在一起？跨社区关系连接了什么？
- 社区摘要是否忠实保留CPUID检测支持、MOVAPS的打包/对齐范围？
- 总摘要相比社区摘要遗漏了什么？引用到一个社区不代表覆盖其中全部关系。
- 查询命中了关系、社区摘要还是总摘要？引用展开是否能追到原始引句？摘要可能没有进入Top-3，不预设层次结构更好。

`COMMUNITY_HIERARCHY_SAVED`仅表示本步保存完成，机械引用检查通过；用户需把终端输出及记录路径交回核对。引用存在不能保证陈述由原文支持，语义、覆盖和幻觉仍待审阅。

这是小图上的Louvain分组与两层递归摘要教学入口：没有UMAP/GMM语义聚类、向量索引、自然语言自动路由或完整大型手册评估，不代表完整RAPTOR/GraphRAG复现。普通关系叶子与生成摘要信息预算不同，不计算公平准确率排名。不能因运行本步就标记整个3-7完成。

## 已做的离线验证

预览验证冻结来源，得到3个修订图社区；全部14条关系恰好分配一次到社区或跨组摘要输入。6项自动测试覆盖输入来源/关系覆盖、孤立节点、越界与重复引用拒绝、递归来源展开与环拒绝、正常模拟响应、截断及坏JSON停止且不重试。模拟响应仅用于检查代码，没有正式模型成绩。

来源为本实验冻结的官方`graphrag_indexer.py`中的Louvain分组与社区摘要思路，以及`raptor_indexer.py`的逐层摘要思路。当前入口独立实现上述教学子集，原官方文件未改。
