## 先理解本次比较

3-6主要研究候选的召回、融合与排序，3-7进一步观察“知识怎样组织”影响能拿到哪些证据。

本步使用官方人工整理的Intel x86 SIMD小知识库：10个实体、13条有向关系、1个父摘要和7个叶子引用。比较两种结构化视角与独立片段检索：

| 方式 | 本步实际操作 | 重点观察 |
| --- | --- | --- |
| 扁平片段 | 对实体描述计算词频余弦，返回前3 | 找回哪些独立描述，是否已包含所需事实 |
| GraphRAG式图 | 从实体名字出发，沿已有关系边遍历，最多3跳 | 能否把起点与答案节点连成可检查的路径 |
| RAPTOR式层次 | 直接展示预写父摘要及其叶子引用 | 概述与细节如何通过父子关系组织 |

这一步没有调用MiniLM或BM25，也没有模型生成答案。图谱边、父摘要和题型路由都已人工写好，不是LLM抽取、GMM/UMAP聚类、社区发现或递归摘要的成绩。

三个官方原问题分别为：

1. 运行ADDPS前，需要把哪个控制寄存器位置1？观察词面片段与图关系链。
2. SSE与AVX使用的向量寄存器有什么区别？观察沿同一种关系对齐事实。
3. 概述x86的SIMD指令集。观察预写父摘要与叶子细节。

图侧起点采用实体名称最长子串匹配，不是通用实体识别模型；第一题控制位类型与“需要启用”关系、第二题实体与“使用寄存器”关系均按固定题型预先指定。第三题直接展示固定摘要，不根据查询执行自动树检索。

## 如何解释输出

如果扁平侧已经命中控制位描述，不能说它“完全找不到答案”；图侧的额外价值在于返回从指令到控制位的明确关系路径。父摘要是作者预写的，不能把直接展示它当成模型概括成功。

图中包含额外人工关系，例如指令属于哪种扩展，并非每条关系都在对应实体描述中显式出现。因此本次是表示与查询方式的示意，信息预算不相同，不是算法或模型的公平性能比较；不计算方法准确率，也不预设结构化一定更优。更完整的RAG系统还可在召回后由模型综合片段，本演示没有测试这一点。

示例摘要中的MMX、使能条件等不是本次自动核实的事实；原图与叶子引用也不等于摘要全部内容的逐条证据。运行结果只说明已有结构如何被查询，不替代真实文档的事实核验或完整硬件配置说明。
