## 先弄清楚评什么

| 层次 | 本地将逐步检查的问题 |
| --- | --- |
| 基础回忆 | 换一个会话后，能否准确说出用户明确提供的事实？ |
| 多会话检索 | 能否合并不同会话的信息，并区分不同人、不同时间的状态？ |
| 主动服务 | 能否把相关的旧事实联系起来，主动指出当前任务中的遗漏？ |

官方正文描述每层20个用例，并使用LLM评委评分。当前02/03已改为直接加载固定版本的官方用例、提示词与评分函数；原01的虚构例子仅作可选概念材料。60题已有生成尝试记录，尚未完成全部可评分答案的独立评分，不复用官方历史得分作为自己的成绩。

## 当前下一步：固定配置批量评估

按[60题批量指南](07_官方60题批量评估指南.md)运行07的judge阶段，指定已有批次official_batch_20261017_103939_726412。只对5份未评分的完整回答新增DeepSeek评分，银行成绩复用，54份截断记录单列，不重跑writer或补0分。评分后汇总三层表现、生成完成率及评分覆盖；实验不要求全部答对。四格式比较另属3-2。

## 分步入口

流程说明：[02_官方用例阅读指南.md](02_官方用例阅读指南.md) → [02_官方用例生成记忆与回答.py](我的代码/02_官方用例生成记忆与回答.py)。默认是官方第一层第一题，1个会话、90条消息，预计2次本机模型调用。

核对02结果后，使用[03_官方用例独立裁判评分.py](我的代码/03_官方用例独立裁判评分.py)，将02的record.json路径作为--record参数。它最多发出1次独立DeepSeek请求，使用已有项目密钥，可能计费；不重跑本机步骤。

本地适配直接加载官方run_evaluation.py的原始提示词和评分函数。记忆调用每次只读已有记忆和当前会话，答题调用不读旧对话或评分标准，评分调用才读取完整来源。先保持notes格式，完整单题核对后再推进60题和3-2四格式比较。

原[01阅读指南](01_阅读指南.md)与[虚构对话脚本](我的代码/01_提取并保存长期记忆.py)作为可选概念材料保留，不再是正式实验前置步骤。

## 环境与证据

使用根目录Python3.11环境，已有requests、PyYAML、OpenAI SDK及本机Ollama。PyYAML已补为直接依赖并离线更新锁文件，没有安装新包。官方资料版本、全部下载哈希见[manifest](官方资料/manifest.json)，实际60题结构与请求预算见[用例清单](官方资料/用例清单.json)。

`OFFICIAL_MEMORY_AND_ANSWER_SAVED`只表示本机单题生成并保存了记忆与回答；`OFFICIAL_SINGLE_CASE_SCORED`只表示该题已得到独立裁判结果。回答正确、裁判通过、60题完成和四格式比较完成是不同结论。
