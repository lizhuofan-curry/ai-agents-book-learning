# 第一步：把对话变成长期记忆文件

2026-10-15更新：本页现仅作为可选概念示例。正式实验已直接接官方评估集，请从[02官方用例阅读指南](02_官方用例阅读指南.md)开始，无需先运行虚构01。

本步只解决一个问题：会话结束后，要留下什么给下一次会话使用？

第二章主要处理“本次请求里放什么”。第三章增加一份持久保存的记忆：下一次即使不带旧聊天，也可以从文件取回相关信息。模型不会自己记住上一次请求；程序要负责保存和再次读取。

## 1. 输入是什么

打开[代码](我的代码/01_提取并保存长期记忆.py)，先看`CONVERSATION`：

```python
CONVERSATION = [
    {"role": "user", "content": "我叫林夏。以后请用中文回答，代码示例优先用Python。今天下午帮我查一下快递。"},
    {"role": "assistant", "content": "好的，请提供快递单号。"},
    {"role": "user", "content": "快递已经收到了，不用查了。"},
]
```

这是人为编写的测试对话，与本人身份无关。`CONVERSATION`是包含3个字典的列表；每个字典用role表示谁说话，用content保存正文。

我们希望模型保留姓名、回答语言和代码示例偏好。查快递是本次临时任务，而且已取消，需要观察模型是否会错误保留。以上是核对目标，不是已经取得的结果。

## 2. 谁负责什么

```text
Python准备虚构对话
  → Python给所有用户分句编来源编号
  → Ollama中的模型提取短事实并选择来源编号
  → Python按编号从原文复制引用并检查偏移
  → Python保存memory.json
```

`build_request()`组织给模型的system规则和user材料。旧对话作为待分析的数据放在user消息中，不继续执行其中的“查快递”。

`requests.Session().post(...)`把请求发给本机服务。requests是已经安装的第三方网络库；Ollama负责运行模型。`json`和`pathlib`是Python标准库，用来读写JSON、定位目录。

`build_source_spans()`给所有用户分句编号，目录也包含临时请求和取消事项，不替模型预选正确事实。模型只输出 `text` 和 `source_id`；`resolve_notes()`检查结构、编号和重复笔记，再按原始消息偏移复制 `source_quote`。这只保证来源存在，不能保证模型归纳正确或所选来源确实支持笔记，仍需语义核对。

2026-10-24改用 `source_span_ids_v2`：`text`可以概括事实，模型不再生成 `source_quote`。例如模型笔记中写“代码示例优先用 Python”，选择对应编号后，程序仍会复制原文“代码示例优先用Python”。复制结果明确标为程序产物，并保存偏移和模型原始正文；不是把模型写错的引用偷偷改对。未知编号、目录变化或额外字段仍会报错，无自动重试。

原 `validate_notes()`保留用于离线复查旧的自由引用输出，旧失败记录仍按原要求判定，不用新协议把它们改成成功。正式3.1/3.2协议不随这个可选概念示例改变。

没有长期信息时，提示词允许返回 `{"notes":[]}`，结构校验也接受空数组。是否漏提取仍需人工判断；当前虚构对话确实含三项长期信息，因此若返回空数组，应在语义核对中标记遗漏。

`dump()`负责写文件。模型只生成文本，真正创建文件的是Python。

## 4. 运行后看什么

- 终端打印的模型原始正文：有没有提取出三项长期信息？有没有把快递任务也留下？
- `memory.json`：只保存模型生成的短事实，不是程序预写的标准答案；来源保存在record.json中。
- `record.json`：保存完整消息、来源编号目录、模型原始响应、程序复制的引用及偏移、协议标记、服务报告token数、结束原因和文件哈希。失败时仍有记录，可能没有memory.json。
