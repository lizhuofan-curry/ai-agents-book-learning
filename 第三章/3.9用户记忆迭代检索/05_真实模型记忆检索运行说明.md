# 第三步：普通与真实模型自主记忆检索

2026-10-24：入口准备，正式模型实验待用户运行。

## 运行

确认既有Ollama服务和qwen3.5:9b可用，在项目根目录执行或打开04点击运行：

```bash
.venv/bin/python "第三章/3.9用户记忆迭代检索/我的代码/04_单次与模型自主记忆检索.py"
```

普通组最多1次本机模型请求，自主组最多4次请求/3次实际检索，总计最多5次。无预热、自动重试、云端请求、嵌入、依赖安装或模型下载。`--preview`校验来源/分块与索引，不执行正式问题检索或模型请求。

## 两组流程

同一官方两会话6块、仅原消息文本的BM25、每次Top-3。普通组直接检索原问题一次，模型据命中片段回答；自主组从问题出发，自行生成search查询，程序返回片段，再由模型选择继续search或answer。

动态复用3-8已有的请求、JSON动作及控制循环，替换为通用记忆任务提示和Top-3，不改3-8源码，不使用法律提示或评分。JSON动作不是Ollama原生tool_calls，只允许知识库检索。模型只能看到本组问题和命中材料（含会话时间、来源编号），看不到全库、预期答案、确认号标记、车辆正则、模板追查步骤、另一组输出或评估结果。

两组均强调区分对象、已确认与仅讨论的安排、变化与时间；不向模型点名车辆或告诉它哪辆已预约。原对话为英文，提示可用同语言检索，中文回答。来源与时间信息用于审阅，不保证模型会正确使用。

采样与3-8控制入口一致：temperature=0、seed=42、think=false、2048输出上限、16384上下文、600秒读取超时。按普通组再自主组串行运行，历史消息分开；没有控制顺序、缓存或热机效应，时间不作严格性能排名。

## 保存与检查

记录保存`运行结果/live_memory_时间/record.json`，保留完整请求、HTTP响应、每次检索片段/来源、token、时间和停止原因。每组结束后统计确认号/第二辆车标记是否出现，该统计不返回给后续模型。覆盖100%不表示预约状态、对象归属或日期解释正确。

`LIVE_MEMORY_COMPARISON_SAVED`只代表流程保存。查看每组状态：answered_review_pending为格式有效回答但语义待核对；budget_exhausted为3次检索后仍想查，未强制作答；repeated_query_stopped为重复查询被程序阻断；failed为技术或协议失败。某组失败后继续另一独立组，用户中断则停止整个实验。失败也先反馈，不自动重跑。

重点核对车辆归属、客服建议是否被当成用户确认、确认号与服务范围是否有来源、时间是否矛盾。单个测试用户不能证明跨用户隔离。本步是单题教学范围，不是官方60题campaign、独立LLM裁判或模型能力排名。

离线预览及4项适配测试检查来源/提示无答案泄露、检索适配来源保留、独立消息及模型选择查询、预算耗尽不强制作答。正式模型请求尚未执行。
