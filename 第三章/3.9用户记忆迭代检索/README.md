# 3-9：用户记忆的迭代检索

2026-10-24，第一步阅读及分块入口已准备，正式运行待用户完成。本步不检索、不生成回答、不调用模型。

## 运行

在项目根目录执行，或在VS Code打开01并点击运行：

```bash
.venv/bin/python "第三章/3.9用户记忆迭代检索/我的代码/01_阅读会话与固定轮次分块.py"
```

无需启动Ollama，无新依赖安装、模型下载或网络请求。仅验证来源和会话规模可加`--preview`，不正式分块或创建结果目录。

## 资料与步骤

使用官方`layer2_01_multiple_vehicles`测试用例，两个历史会话、194条消息，不是用户本人的真实经历。第一步保留当前问题与原始对话，按官方fixed-round逻辑独立实现20轮一块、重叠2轮，遇assistant收尾且当前至少2条消息为一轮，最后残余消息单独保留。分块不能跨会话，每条消息带原始编号、会话ID和会话时间；时间是历史会话元数据，不是每条消息独立时间，也不是本次运行时间。

本入口不执行官方config的load_dotenv，不读取.env，不把用例标题、description、预期答案、评分规则写入记忆块。原始YAML仍包含官方完整标注，后续模型提示须继续隔离这些字段。只采用原对话及会话元数据，不生成邻块摘要或预览；因此不把人工添加信息当作记忆抽取成绩。

运行后保存`运行结果/conversation_chunks_时间/record.json`和可直接阅读的`原始会话与分块阅读.md`。终端显示会话与块边界，不把194条消息全打印出来。看到`MEMORY_CONVERSATION_CHUNKS_SAVED`后发回输出和路径，核对后先阅读Markdown：分清两辆车、已确认与仅讨论的服务状态、信息来自哪次会话。重叠消息重复出现不表示新事件。

## 后续范围

第一步只核对记忆材料及分块完整性；第二步再比较单次检索与规则多步检索；第三步再接入真实模型自主查询。官方offline_demo.py用车辆实体规则及固定查询模板追查，不是LLM自主规划，其“标记出现”指标也不能代替事实、时间与回答语义核验。官方历史百分比不作为个人实验结果。

本例只有一个测试用户、两次会话，不能据此宣称验证跨用户隔离或所有偏好更新。正文中的时间与出处保留，只能支持进一步分析，不自动完成旧信息覆盖判断。
