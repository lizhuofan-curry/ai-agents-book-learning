# 实验1-1：上下文的关键作用

以[官方实验README](https://github.com/bojieli/ai-agent-book/blob/main/chapter1/context/README.md)为依据，用一个固定例子逐步学习。官方源码在学习时在线查阅，代码逐步写入`我的代码`。

## 现在先配置项目解释器

整个AI_Agents_Book项目使用同一个Python3.11环境：

```text
E:\AI_Agents_Book\.venv\Scripts\python.exe
```

在PyCharm解释器设置中添加本地解释器，选择现有环境，浏览并选择上述文件。项目根目录的pyproject.toml和uv.lock管理依赖，配置见[项目说明](../../README.md)。

## 第一步：认识计算器工具

固定任务：“计算(125+375)*8。”

官方calculate接收算式字符串，调用safe_eval得到结果，再返回算式、结果和类型。这里的4000由Python工具算出。

```python
expression = "(125 + 375) * 8"
result = 4000
```

理解输入是什么、程序处理了什么、返回了什么，再动手写和运行第一个工具。这里还没有调用模型。

## 第二步：模型怎样选择工具

向模型提供用户任务和计算器工具定义。观察模型提出的工具名称和参数，区分“模型提出调用请求”与“Python实际执行函数”。

## 第三步：工具结果怎样返回给模型

程序执行工具后，把模型的调用消息和与调用编号对应的工具结果加入消息列表，再请求模型。找出下一轮请求中模型实际看到的4000。

## 第四步：读懂完整循环

```text
用户任务→模型提出工具调用→Python执行→结果写回消息→模型决定继续或回答
```

先跑通完整模式，再解释每轮消息。普通最终回答与工具调用请求的处理方式不同，迭代上限用于结束无法收敛的循环。

## 第五步：五组上下文消融

保持同一模型、同一任务和同一迭代上限，只调整模型收到的上下文。

| 模式 | 实际移除的信息 | 观察重点 |
|---|---|---|
| full | 无 | 能否依据工具结果完成任务 |
| no_tool_calls | 工具定义 | 没有可调用工具时如何回答 |
| no_reasoning | 历史中可回传的reasoning_content | 与基线是否存在有效差异 |
| no_history | 当前任务之前积累的执行轨迹 | 是否重复行动 |
| no_tool_results | 工具结果消息的内容 | 无反馈时如何继续 |

去掉reasoning_content不等于禁止模型内部推理，隐藏工具返回内容也不等于工具没有执行。模式名称和实现以官方代码为准。

正式任务使用官方run_experiment_1_1.py的固定多币种收入任务及评分标准。到这一步再核对官方代码，准备与项目目录匹配的运行入口。现在无需一次完成所有步骤。
