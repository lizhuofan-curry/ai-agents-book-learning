## 从写在代码里到运行时传入

07把问题写在Python文件里，08用input等待输入。09在启动程序时就收到问题与设置，然后进行一次问答。

例如，运行时传入：

```text
"请搜索Python官方文档，解释Python3.11的ExceptionGroup，并提供来源链接。" --max-steps 5 --quiet
```

程序解析后，相当于得到：

```python
args.query = ["请搜索Python官方文档，解释Python3.11的ExceptionGroup，并提供来源链接。"]
args.max_steps = 5
args.quiet = True
args.output = None
```

这里是取值示意；这些值实际由parse_args生成，不需要自己写上述赋值。args是Namespace对象，用args.max_steps这样的点号访问属性。

## 先看新增的四行定义

打开[09_命令行参数.py](我的代码/09_命令行参数.py)，先看build_parser。

```python
parser.add_argument("query", nargs="*")
parser.add_argument("--max-steps", type=int, default=5)
parser.add_argument("--quiet", action="store_true")
parser.add_argument("--output", "-o")
```

add_argument告诉解析器“允许接收什么”；它此时没有调用模型，也没有搜索。

| 定义 | 运行时的写法 | 解析后的值 |
|---|---|---|
| query | "一个完整问题" | args.query是字符串列表；nargs="*"允许零个或多个词 |
| --max-steps | --max-steps 5 | args.max_steps是整数5；省略时使用default=5 |
| --quiet | --quiet | args.quiet是True；省略时为False，无需再写True |
| --output、-o | --output 命令行练习.json | args.output是路径字符串；两种名称代表同一参数 |

问题用英文双引号括起来时，其中的空格也属于这个问题。" ".join(args.query)把列表中的词用空格连接成一个问题字符串。--max-steps中的连字符会转换为属性名里的下划线，所以代码读取args.max_steps。

parse_args(argv)才是真正读取参数的地方。main()没有传入argv时，argparse读取启动程序时的参数；本地模拟检查可以给main传入列表。本步先掌握正常运行方式即可。

Python官方说明见[argparse文档](https://docs.python.org/3.11/library/argparse.html)。

## 接到已有Agent上

```python
agent = WebSearchAgent(..., verbose=not args.quiet)
answer = agent.search_and_answer(question, max_iterations=args.max_steps)
```

第一行把显示开关传给对象：填写--quiet时，args.quiet=True，not True=False，verbose=False。仍然会调用真实API、执行搜索，并保存完整记录；最终回答仍会打印。

第二行把问题和轮数上限传给已学过的方法。5限制的是模型请求轮数，每轮可以提出多个搜索调用。5轮以内拿到stop且回答非空就完成；到第5轮仍要求工具调用，则按已有方法报告达到上限，不能当作完成。

--output指定文件路径。相对路径从本实验的运行结果目录开始；绝对路径使用指定位置。指定已有文件时会覆盖它。省略--output时，自动在运行结果/命令行问答中生成时间文件名，保留之前的记录。

配置加载、Agent循环和记录保存均沿用已有代码；新增的run_options在JSON中记录这次max_steps和quiet的取值。

## 本次真实运行：观察轮数上限

用户已先运行无参数入口，看到帮助并正常退出。随后创建PyCharm运行配置，填写ExceptionGroup问题与--max-steps 5。实际解析结果为query包含完整问题、max_steps=5、quiet=False、output=None。

| 模型请求轮次 | 发送消息数 | 模型提出调用数 | 实际执行搜索数 |
|---|---|---|---|
| 1 | 2 | 3 | 3 |
| 2 | 6 | 4 | 4 |
| 3 | 11 | 3 | 3 |
| 4 | 15 | 3 | 3 |
| 5 | 19 | 3 | 0，已到上限 |

共5轮模型请求、13次搜索；13次均返回HTTP200、succeeded。第5轮仍为tool_calls，表示还没有最终答案。

类中的停止分支为：

```python
if iteration == max_iterations:
    self.status = "max_turns_reached"
    raise RuntimeError("模型请求轮数已达到上限，仍有新调用，尚未完成问答。")
```

本次iteration与max_iterations均为5，因此执行raise，跳出Agent方法；第5轮的新工具调用没有被执行。5限制的是模型请求轮数，每轮可以包含多个搜索，不是最多搜索5次。

09的except接到这个异常，打印“本次问答失败”，随后raise继续抛出。异常向外传播前，finally仍会保存记录，所以先看到JSON路径，再看到Traceback。

保存记录为status=max_turns_reached、answer_complete=False、answer为空；最终历史20条，最后的assistant含3个待执行调用。文件为[20261005_164034_952797.json](运行结果/命令行问答/20261005_164034_952797.json)。这次验证了参数生效、上限停止与失败记录保存，问答尚未完成。

## 下一步只练习quiet显示开关

在刚才成功运行的脚本参数末尾添加--quiet：

```text
"请搜索Python3.11官方文档，用100字以内解释ExceptionGroup，给出1个官方链接。完成一次搜索后，根据已有结果回答；如果证据不足，请明确说明。" --max-steps 5 --quiet
```

首先观察参数变化：args.quiet从False变为True。创建Agent时verbose=not args.quiet，因此verbose变为False。

| 内容 | 不填写--quiet | 填写--quiet |
|---|---|---|
| 模型轮数、调用ID、搜索参数和工具状态的过程打印 | 显示 | 隐藏 |
| 入口打印的解析参数、问题、最终回答与保存路径 | 显示 | 显示 |
| 真实模型请求与搜索执行 | 执行 | 执行 |
| JSON中的conversation_history、trace与api_turns | 保存 | 保存 |

这会发起一次新的真实问答，搜索次数和答案可能与刚才不同。默认仍按时间保存独立文件。完成后检查JSON中run_options.quiet=True及真实调用记录；quiet控制显示，不控制工具是否执行。
