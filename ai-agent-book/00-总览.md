## 三、正文怎么读：三层阅读法（官方建议）

正文**不是某个 SDK 的逐步教程**。正文里的伪代码只回答"状态怎样流动、哪一步能停、哪类信号参与验证"；完整实现、模型适配、测试、证据都在章级实验里。也别把某一次实验的具体 API 写法当成通用架构。

| 层级 | 先看什么 | 暂时跳过什么 | 回答什么问题 |
| :--: | --- | --- | --- |
| **Starter** | 项目 README 的目标、最小命令、验收条件；正文对应 skeleton | 凭据加载、UI、provider adapter、长篇原始日志 | 这个实验要证明哪条机制？ |
| **Builder** | 入口函数、核心循环、状态/消息 schema、工具和验证器 | 与机制无关的兼容层、部署脚本 | 哪一个变量改变了行为？ |
| **Maintainer** | 测试、失败处理、证据格式、manifest/hash、回滚路径 | 只在改动实验时才需要的第三方细节 | 结果是否可复核、失败是否被诚实记录？ |

## 五、本教材的三个使用规则

1. **正文看骨架，实验看实现**：读完一章正文，去对应章目录挑 Starter 实验跑通，再回头改一个变量看行为变化。
2. **只信留存证据**：每个实验目录里的 `validation/`、`EXPERIMENT_LEDGER.md`、`manifest.json` 是"做完了"的判据；README 说"已实现"不等于验收过（台账里就有一批 `🚧 Incomplete`）。
3. **不进 `agent_study/` 的 git 范围**：仓库是外部资料，放在 `D:\hermes\` 根下；本笔记只做索引与排期（与 `_reference/`、`调研/` 同样的分工）。
