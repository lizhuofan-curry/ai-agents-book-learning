## 本次比较什么

六策略处理同一组3份材料，最后回答同一个问题：6位虚构项目发起人的最新机构、状态与来源。材料有无关内容及一条旧状态，检查摘要能否保留精确代码、日期和来源关系。标准答案单独保存，绝不作为摘要模型或问答模型的输入。

| 策略 | 操作 |
| --- | --- |
| no_compression | 原文直接保留 |
| individual | 每份材料独立做通用摘要，再拼接 |
| combined | 3份原文合并做通用摘要 |
| context_aware | 合并摘要时加入当前研究问题 |
| citations | 在任务感知摘要中显式要求日期、来源和URL |
| windowed | 逐份追加；达到字符预算80%时批量压缩旧的未压缩块，最新一份保留全文；不重复压缩已标记块 |

先运行[01_六种压缩策略对照.py](我的代码/01_六种压缩策略对照.py)，使用根目录共用解释器。只需现有requests包及本机Ollama中的qwen3:0.6b，无需安装或读取API密钥。使用本机/api/chat，显式指定num_ctx=16384、关闭thinking、temperature=0，保存全部原始响应与服务报告token数。

默认每策略1次探索，可在运行参数中设置`--repeats 3`。不同策略顺序固定随机化；同一重复内材料、任务和评分完全相同。预热1次不计入各策略开销。总请求数由实际摘要事件与问答决定，记录最终打印准确次数，不把“六策略”误算成“六次请求”。

## 如何读结果

1. `compression_ratio`是保留证据字符数/原始证据字符数，越小越短；包含摘要标记及块分隔符，不是token节省率。
2. `all_prompt_tokens`和`all_completion_tokens`包含本策略全部摘要和最终问答调用，预热单列。压缩后的最终输入更短，不保证全流程消耗更少。
3. 最终回答分别评12个事实字段（6人×机构/状态）和6个来源。JSON缺失、重复或漏人时结构检查失败，不拿部分答案当全部正确；原始回答可人工复核。
4. `character_budget_blocked`是代码设定的6000字符教学门限拒绝，不是Ollama真实上下文溢出。摘要过长也会被拒绝，不偷偷截断或按答案补齐。
5. window_checkpoints记录触发前后长度和已压缩块；calls.json包含完整提示、响应、耗时、done_reason与token用量。保存于独立时间戳运行目录。
