## 本次任务与比较

| 功能 | 小任务 | 检查的行为 |
| --- | --- | --- |
| 时间戳 | 模拟时间跨过午夜后，读取当前“昨天”创建的日报并提交原文 | 是否选择10月13日的文件，而不是沿用10月12日 |
| 工具计数 | 一个文件已经失败读取3次，用户允许改读备份 | 是否避免第四次读取、使用备份并提交 |
| TODO | 三步任务已完成读取和复制，仍需提交原文加上后缀 | 是否完成剩余步骤、避免重复已完成的写入 |
| 详细错误 | 切换目录后读相对路径失败 | 是否定位实际路径、读取后提交，避免猜内容 |
| 环境状态 | 工作目录已从project变成archive，两处有同名文件 | 是否按当前目录读取并提交正确文件 |

每类任务比较三个配置：`disabled`关闭提醒，`single_feature`仅打开对应功能，`all_features`五项全部开启。共5×3=15个多轮任务，各配置/任务仅运行1次。

同一任务的三组初始模拟文件、历史操作、时钟、目标、工具定义、系统规则、模型参数相同。原始历史保留，开关改变事件前缀、错误诊断及末尾状态提示。每个任务结束后重建模拟世界，不让上一组的文件或次数影响下一组。

时间clock在原始工具结果中始终可见；时间功能额外添加事件前缀与当前时间，避免基线完全没有时间证据。错误功能额外提供参数、调用栈及恢复建议，测的是完整提示干预，不能把差异全部归因于排版。所有组具有相同的TODO工具，程序依据已发生的工具结果更新进度；TODO开关主要改变进度摘要是否可见，不代表完全禁用内部任务跟踪。

本次1次预热，15个任务每个最多6轮模型请求、12个新模拟工具调用。正常情况下请求尝试在16～91次之间，实际数由工具循环决定；上限只是保护，不要求任务用满6轮。已预置历史的模拟操作单列，不算本次新增工具调用，也不引发模型请求。

每轮都保存完整输入、临时状态栏和原始响应，执行工具后再存事件与最新模拟状态。状态栏临时追加到本次请求末尾，不改system，也不永久堆积旧状态；这仍可能影响上轮后缀的前缀缓存复用，不宣称零缓存成本。

本学习版关闭思考，temperature=0、seed=42、统一512-token输出预算。与2-8的HF思考模式不同，不跨实验比较速度或权重。这里只调用本机服务，工具由Python在内存中执行：`/lab`是模拟路径，不是电脑磁盘目录，没有模型指定的真实磁盘写入或Shell执行。真实运行记录由固定目录保存，与模拟文件相互独立。

## 结果怎么看

重点看`对照汇总.md`中，同一任务的三行：

- 任务通过：目标原文确实被读取，模拟报告内容精确符合用户要求，得到最终回复，没有越过读取上限或重复完成的写入。
- 模型响应数：该任务循环了多少轮。
- 新工具调用/错误数：只统计本次模型提出并在模拟世界执行的新动作。
- 重复完成写入：在已正确复制/提交后又执行同样写入。
- 被拒请求：模型提出超限或越出模拟范围的动作。程序拦截不能算模型遵守规则。

`answered`只是模型停止并给出非空正文，不等于任务通过。`truncated`、`round_budget_reached`、`tool_budget_reached`等状态保留为未完成。文件内容正确而无最终回复也单列，不隐去失败。错误后的合理恢复可能产生错误记录，不能仅以错误少为唯一优劣标准。

完成标记`STATUS_TECHNIQUES_OBSERVATION_COMPLETE`表示15个任务均得到测量记录，不表示15个任务都通过，也不代表官方60%→95%或15→21轮历史结论在本机被复现。

运行后反馈末尾逐任务对照及实际请求数，再核对模拟文件与完整轨迹、更新[实验记录](实验记录.md)。小样本可能三组都成功或都失败，按实际结果记录。
