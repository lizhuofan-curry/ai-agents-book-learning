# 实验2-4：提示工程消融（本地单步工具决策）

参考[官方提示工程实验](https://github.com/bojieli/ai-agent-book/blob/main/chapter2/prompt-engineering/README.md)的语气、规则组织、工具描述三个维度，制作同任务对照。官方使用τ-bench完整客服环境与多轮任务终态验收；本学习版用现有本机qwen3:0.6b，检查单次工具选择和参数，不执行工具，不将它称作τ-bench任务成功率。

## 运行

在PyCharm保持根目录解释器，运行[01_提示工程六组对照.py](我的代码/01_提示工程六组对照.py)。无需新增依赖或模型下载，本机Ollama需可用。

预热1次，六组各5道固定题，共31次请求。与2-3不同，这次每题只有一次模型决策，不分基础/追问配对。固定采样设置、同一模型、同一题集，打乱测试顺序；此处看决策质量，不比较延迟加速或费用。

| 组别 | 相对基线改动 |
| --- | --- |
| baseline | 专业语气、分节规则、完整工具描述 |
| tone_casual | 仅改开头为轻松语气 |
| tone_emphatic | 仅改开头为强调语气 |
| wiki_shuffle | 同样五条规则打乱排列、去掉小节标题，规则正文不删减 |
| no_tool_desc | 删除工具及参数的描述，保留名称与参数schema |
| combined | 轻松语气、规则打乱、删除描述同时生效 |

五道订单题覆盖30天可退边界、31天过期、拆封转人工、尚未确认、已退款防重复。题目中的状态直接给定，不查询或修改真实订单。

为了隔离文档作用，工具故意命名为op_a～op_e，均接受order_id；用途在description中说明。这会放大去描述后的困难，不能外推为描述性工具名下必然出现相同变化。系统规则谈业务动作，不直接泄露动作与工具名的对应答案。各组接收相同规则内容；组合组用于观察叠加，不用于单项归因。

分别记录：工具名正确、参数是否恰好为该订单的order_id、两者是否均正确。多调用、无调用、参数错误均可作为失败样例保留。每组仅5题，原始差异只用于学习；不预设基线必须优于消融组。

成功标志PROMPT_ABLATION_COMPLETE表示全部测量正常完成，不代表全部决策正确。保存record.json和对照汇总.md；助手仅生成代码、检查语法，模型请求由用户执行。

## 本次实测

用户于2026-10-11完成31次请求。六组工具与参数均正确数依次为1/5、1/5、1/5、2/5、0/5、1/5；30题中23题选择op_e，组合组2次空响应。基线表现较低，每组仅5题，不能据此建立提示词优劣排序。详见[实验记录](实验记录.md)。本地单步测量完成，官方完整τ-bench未复现。
