# 第五步：让模型查完整日志

打开`我的代码/11_模型查找完整日志证据.py`点击运行，或：

```bash
.venv/bin/python "第四章/4.4执行工具/我的代码/11_模型查找完整日志证据.py"
```

需本地Ollama及已安装的qwen3.5:9b。入口自动使用已有SDK环境，不安装或下载。最多3次本机模型请求、2次MCP工具调用，温度0、种子42、每次输出1024上限、上下文16384；不预热、不重试、无云端调用。

问题是“请检查完整日志中是否存在CHECKPOINT，如果有，给出文件行号和原文。”复用已核对的long_output_20261025_185021_477189中的1000行原始日志，指纹锁定，只读使用。模型新会话初始只收到头尾片段、截断标记、总行数及工具声明，不接收上一轮按行读取结果、生成代码、核对项、标记原文、所在行号或完整日志。用户已经知道答案，本步骤不是未知样本测试。

模型可用search_log按字面关键词搜索匹配文件行号，或read_log_lines每次读取最多20行原文。搜索最多返回20个行号并注明总匹配数和截断状态，避免用宽泛关键词重新塞满上下文。行号1起算，日志内部编号可能另有起点。模型需依据真实返回决定工具及参数，客户端不预写顺序，也不把应查位置代填给模型。

工具路径由本地服务绑定到这份冻结日志，模型不能请求其他文件。读取原文会在客户端再与完整文件对应位置比对。保存源码/来源指纹、原始模型请求及HTTP响应、工具目录和SDK解码结果、模型看到的片段。旧日志及记录不改，不生成新的模型日志来源，不声称底层stdio全文已保存。

结束标记MODEL_LOG_LOOKUP_RUN_SAVED只表示轨迹保存。log_evidence_answer_saved_review_pending表示模型调用读取工具，拿到了含目标标记且与原文件一致的行，最终回答仍需核对引用、行号和原文；answer_without_marker_source_review_pending表示有回答但没有取得目标原文；incomplete表示异常或预算内未完成。不能只看是否提到CHECKPOINT就自动判断成功。

本步骤明确告知了要找的关键词，测试的是按目标取证，不是自主发现未知异常。日志中间位置是人为设置，且没有对比不同截断策略或统计准确率。先看模型是否继续访问完整证据，后续再整理学习范围，不反复针对同一例改提示声称普遍提升。

准备阶段预览和4项离线检查通过，模拟模型配合真实SDK stdio验证了初始输入隔离、按返回行号继续读取、提前回答单列、读取边界/搜索截断与来源变化拒绝，没有请求Ollama。正式模型运行待用户完成。
