## 本次观察

输入是10个空格分隔的英文词，正确结果apple=4、banana=3、cherry=2、date=1。

1. 正确代码通过compile语法检查后写入文件。
2. 故意含语法错误的代码在写入前被拒绝，broken.py不会生成。
3. 用独立Python子进程运行正确代码，保留命令、退出码、stdout、stderr及文件哈希。
4. 读取真实生成的counts.json，按输入逐词独立计数，核对完整键和值。
5. 在另一工作区运行另一个语法正确但故意把apple改成999的版本。它仍以退出码0结束，却不能通过独立目标检查。

三个层次分别是语法能解析、进程正常结束、输出符合任务。不能只看success或退出码0就声称任务完成。错误版本被检测到才符合本教学练习预期，并不是入口脚本失败；两版输出分开保存，不覆盖正确结果。

成功标记EXECUTION_TOOLS_RUN_SAVED。把输出发回后，重点对比步骤3/4与5/6，查看success与goal_correct为何不同。--preview仅检查代码语法，不执行；--check在临时目录执行全部核对，不生成正式结果。离线检查.py额外核验语法拦截及路径/覆盖边界。正式学习运行待用户执行。
