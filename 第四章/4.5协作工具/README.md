# 4-5：协作工具

第一步先观察本地人机协同：程序创建一个请求，等待你在终端输入决定，再继续或停止任务。没有模型或MCP调用，不能当成模型自主判断或完整协作工具验收。用户已完成同意与拒绝两次正式运行，记录和实际文件已核对。

打开[01_终端人工确认与任务恢复.py](我的代码/01_终端人工确认与任务恢复.py)，点击VS Code右上角“在终端中运行Python文件”。使用原项目.venv，无新依赖，不用启动Ollama。也可以在项目根目录执行：

```bash
.venv/bin/python "第四章/4.5协作工具/我的代码/01_终端人工确认与任务恢复.py"
```

看到请求编号、待决定的事项和目标路径后，点一下终端，输入“同意”或APPROVE，再回车；也可输入“拒绝”或REJECT。默认等待60秒。空回车或其他文字不会批准，也不重置剩余时间；超时、EOF、不可交互输入或取消均不会自动批准。一次运行只处理本次请求，终态不被迟到或重复回复改变。想观察另一条路径，再运行一次即可；每次使用新目录。

请求的具体动作是在本次运行目录创建教学结果.txt。批准前只写record.json审批过程记录，批准后才写教学结果文件，并逐字核对；拒绝或超时则检查教学结果文件确实不存在。所有文件只在新运行目录内，不覆盖已有文件。--timeout可调整等待秒数；--preview只检查参考和入口，不等候回复、不创建运行目录。

运行结果保存请求ID、待执行动作、真实终端回复、状态事件、等待时间、决定和文件核对。HITL_LOCAL_RUN_SAVED表示记录保存，请同时看completed_approved/completed_rejected/completed_timeout等状态；拒绝或超时是正常的停止路径。中断标记interrupted，若中断发生在批准后的文件写入阶段，会记录实际文件是否存在，不能只凭中断字样推断文件一定未生成。

本步是助手依据官方概念编写的精简教学实现，不导入官方通知或配置模块。参考固定提交下的request_admin_approval、respond_to_request、list_pending_requests和超时逻辑；官方CLI另有auto-approve模拟选项，本入口不提供自动批准。官方源码仅作为可阅读参考，manifest保存本地SHA256和固定提交；下载末尾空行规范化，根许可证与官方README许可文字均原样保留。

后续再学习通过MCP传递请求与回复、模型何时需要用户输入等。本步没有创建子Agent、访问浏览器、发送邮件/消息或设置定时提醒，没有读取.env。准备阶段7项离线检查使用虚拟时钟与显式测试输入，另有同意/拒绝/超时3条PTY终端冒烟检查，均通过；回复均明确标为自动化测试输入，不冒充人工回复。测试产物已清理，准备检查.json仅保留检查摘要，正式人工运行待用户完成。

第二步已准备：[03_通过MCP提交人工决定.py](我的代码/03_通过MCP提交人工决定.py)，自动使用已有SDK环境，固定3次MCP调用，仍由你在终端输入本次决定；无模型或通知。4项服务端测试和3条真实stdio路径检查通过，测试回复均单独标为测试输入。用户已完成MCP批准路径，真实回复、服务端状态及文件哈希核对通过。详见[运行说明](04_MCP人工确认运行说明.md)。
